| `JS_APP_FETCH_PLAN.md` | **In progress** — stop `web_fetch` reading an un-rendered single-page app as an empty page. The recovery ladder escalated only on a **blocked** fetch or a strictly EMPTY extraction, while every recovery tier has to clear `_MIN_RECOVERED_CHARS` to win — so the direct tier alone won at one character, and an SPA shell leaking a cookie line or a "Loading…" placeholder short-circuited the whole ladder as a successful fetch of a blank page. Adds evidence-based `_looks_like_js_app` detection (SPA hydration markers, or the shape that catches an unknown framework — a lot of HTML and a lot of `<script>` for almost no text), gated behind a thin extraction so a genuinely short real page never burns the heavy solver or the paid Tavily tier; widens escalation to thin-with-JS-evidence with the shell seeded as the fallback so nothing is lost; and — the half the model actually reads — replaces "That page had no readable text" with a message that says it is a JavaScript app, that the renderer and stealth browser **were already tried**, and that this is not evidence the topic doesn't exist. J1 ✅ (detection, escalation, `FetchResult.js_shell`, the tool messages, `web.js_shell_unrecovered`, full unit coverage). J2 ◻️ (live on-box validation via `POST /api/debug/fetch`, whether the reader needs a hydration wait, threshold tuning). |
