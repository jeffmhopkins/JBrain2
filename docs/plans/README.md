| `DYNAMIC_PORTAL_FETCH_PLAN.md` | **In progress** — give the research fan a way to actually *query* dynamic government search portals (codename "dinosaurs") instead of laundering an un-queryable portal's empty search form into "no record exists". Per-portal resolver adapters (FL Sunbiz corp search, FL DFS licensee search) turn a name into real, citable result/detail rows via each portal's actual endpoint through the existing SSRF-guarded `WebFetcher` (no new outbound leg), surfaced as `WebSource`s that fold into the `[^n]` registry with zero `deep_research.py` change; plus a precision-tuned "this is a search form, not results" detector (`_is_search_form_page`) so a portal without an adapter degrades honestly. Adversarial review incorporated (revisions R1–R6). Wave order: P3 (honesty backstop) + P1 (resolver framework + `portal_search` tool + FL Sunbiz adapter) shipped; P2 (FL DFS licensee) open. Motivated by the `candidate_profile` failure diagnosed in this repo. |

P1 (the tool + approval + re-injection) and P2 (the continuation runtime) shipped on-branch with unit + RLS-isolation + integration tests; P3 (the `plan_card` view, composer pill, Chats badge, countdown) in progress. |

S1 (detection + default-on solver tier + debug route, full unit coverage) shipped on-branch; S2 (live on-box validation + timeout/cache tuning) open. |
