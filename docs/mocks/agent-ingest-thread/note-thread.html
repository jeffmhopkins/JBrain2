Where a turn can start

Exactly one place: the omnibox send. Selecting a candidate or typing into a question field is local state — it can't fire a turn, so a half-answered block costs nothing and a stray tap can't burn a pass. The block and the composer compose into one message.

close_reading — one call, one statement

Gaps this exposes

resolve_entity, close_reading and ask_owner are absent from the label map in agent/status.ts, so a live pass reads “Using resolve_entity” rather than “Looking up an entity”.

And a half-filled block needs somewhere to live if you close the app — draft state per thread, or the answers are gone.

Why the omnibox is the only submit. Interactive components inside a transcript are cheap to add and expensive to get wrong: if each answer posted, three taps would be three turns, three clarification blocks and three re-ingests — the exact cost this batching exists to remove. Making the components inert and letting the composer's existing send carry them means there is one submit affordance in the app, and it is the one already there. Still open: whether a partial send is allowed, and what pushes when the thread starts waiting.
